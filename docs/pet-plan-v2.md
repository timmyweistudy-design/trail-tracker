## 1. 查證到的事實（這次的方案都根據這些）

### G1 動作「最後一下被切掉」——不只神龍，是全站共通的毛病
`flash(class, 毫秒)` 等寫死的毫秒數就把 class 拿掉；但 CSS 每一階的動畫長度不一樣。class 一拿掉，角色**瞬間彈回原位**＝看起來頓一下。對照表（程式等多久 vs CSS 實際多長）：

| 動作 | 程式等 | CSS 實際 | 被切掉的角色 |
|---|---|---|---|
| 跳一下 `pb-hop`（待機的跳、玩完甩一下） | 900／1100 ms | 蛋 1.4s、幼蟲 1.3s、蝶 1.2s、虎 1.4s、幼龍 1.3s、**神龍 1.6s** | 6 隻（只有狐剛好） |
| 伸懶腰 `pb-stretch`（叫醒、清晨） | 1400 ms | 神龍 1.6s | 神龍 |
| 嚼 `pb-chew` | 360～600 ms | 幼龍 0.9s | 幼龍 |
| 鼓臉頰 `pb-swell` | 640 ms | 0.72s | 全部 |

### G2 神龍玩松果回位「頓一下」的真因（逐格量到）
虛擬時間逐格記錄尾尖位置：第 127 格**尾尖一格跳 16px**，下一格速度掉到 0.2px。那一格正是「舉高甩一下」（`flash("pb-hop", 900)`）結束、開始放回原位：神龍的 `pbRise` 要 1.6 秒，程式 0.9 秒就拿掉 class——**神龍正升在半空，瞬間掉回雲上**，接著放回的補間又從靜止慢慢起步＝「頓」。另外放回原位的那段（第 152 格）也有一次明顯的減速不連續。

### G3 親密「0/5」的原因
- 卡片和拍照顯示的是**心數**＝`floor(親密點數 ÷ 20)`，進度條也是用心數畫的。
- 這幾輪加的來源（摸頭 +1、抱抱 +2、玩 +1）都很小：**飄出「親密 +1」，但數字和進度條都不動**，要累積到 20 點才會變 1 顆心。
- 親密每天會掉 2 點（隔一天沒互動開始掉）。新使用者第一天只摸頭抱抱，幾乎永遠看到 0/5。

### G4 裝扮哪裡粗糙（看截圖）
1. **選單格子**放整隻動物，帽子只佔格子一成，分不出是哪一頂；沒拿到的整隻變灰，連帽子長怎樣都看不到。
2. **13 頂帽子＋配件全擠在一張清單**：買的、每月挑戰、地區、季節限定混在一起，沒有「收集了幾頂」。
3. **帽子本身畫得比角色簡單**：角色有描邊、亮面、陰影，帽子大多是平塗（草帽沒有編織紋、頭巾是一條色帶、芒草穗三根棍子）。
4. **尺寸不一致**：同一頂帽子在神龍頭上明顯比較小；狐、虎的帽子跟耳朵的前後關係沒處理。
5. **不能先試穿**：按下去就問要不要花果實；換上後也看不到在舞台上的樣子，要關掉視窗才知道。
6. 配件（圍巾、鈴鐺）只做了兩件，在裝扮視窗最底下，很難發現。

### G5 第一版還沒做完的
- **R3（使用者出 iOS build 後）**：小工具 Swift 編譯／安裝／顯示、3 天提醒實機、原 27 小工具外觀（睡覺圖、節日圖）、`ios-checklist.md` 全跑一次、A1 確認 build 號
- **R6（社群，使用者決定延後）**：原 3、23～26
- **待使用者確認**：幼蟲要不要改波浪爬行（目前保留 10/06 要的拱身走，只補齊腳）
- 原 16「和夥伴的一年」併進年度回顧（沒做）、原 17「爬升多會喘」（沒做）、原 32 小語種母語校對（只做了自我抽查）
- 效能：神龍**待機**每秒 80ms 腳本（4 倍降速）沒動（只修了餵食時的重複重畫）

## 2. R7：動作與數值穩定（先做，約 1 天）

### R7-1 動作計時統一（修 G1、G2）
- **怎麼做**：`flash()` 改成**等這個 class 真正的動畫結束**——加上 class 後讀 `getAnimations()` 裡由這個 class 觸發的動畫（含子元素），等全部 `finished`；讀不到動畫（減少動態效果、被 `animation:none` 蓋掉）就用原本的毫秒數當上限。呼叫端傳的毫秒數改成「最多等多久」，不再是「等多久」。
- **神龍玩松果**：甩一下改成「升起、甩、落回」一個連續動作——落回雲上的那一刻尾巴才開始放回，放回的補間從尾巴**當下的速度**接著走（不從 0 起步）。
- **怎麼算好**：七隻每個 flash 動作播完，角色位置跟動畫最後一格一樣（不跳）。
- **驗收**：
  - 新偵測器 `pet-anim-cut.test.js`：七隻 × 每個 flash 動作，class 拿掉那一格前後，角色外框位移 ≤ 1px；並列出「程式上限 < CSS 長度」的組合（必須是 0 組）——把這次的對照表變成會紅的測試
  - `pet-motion` 加神龍玩松果整段：尾尖每格速度變化 ≤ 3px（現在第 127 格是 16px）
  - 截圖：神龍玩松果 0.1 秒一格的接觸表，人眼看「沒有掉下來一下」

### R7-2 親密重做顯示與節奏（修 G3）
- **顯示**：卡片改成「♥♥♡♡♡ 37/100」——心照點數**部分填色**（第 2 顆心填 85%），進度條用點數畫；飄出 +1 時**進度條真的往前長一點**、數字跳一下（沿用 +km 的飛進動畫）。拍照、拜訪卡、好友列表同一套。
- **節奏調整**（要使用者同意，見第 6 節）：
  - 每顆心 20 點不變；第一顆心降到 10 點（新手第一天摸頭＋抱抱＋餵一次就看得到第 1 顆心）
  - 掉落：2 天沒互動才開始掉、每天 −1（現在是隔天就掉 −2），而且**不會掉到這一顆心以下**（不懲罰：只是不再往上）
  - 「？」裡多一行：「現在 37 點，再 3 點第 2 顆心」
- **驗收**：`pet-r7.test.js`——摸一次頭，數字 +1、進度條寬度變大；拍照圖上的數字跟卡片一樣；3 天沒互動只掉 1 點而且不跨心；備份合併照舊（`tt_pet_aff` 跟著時間戳）。

### R7-3 小修
- 原 17「爬升多會喘」：記錄中最近 5 分鐘爬升 > 60m 時，地圖上的夥伴偶爾停一下喘口氣（只代表角色，不代表使用者）
- 神龍待機效能：待機時尾巴的鱗片、腹甲只在繩波相位變化夠大時才重畫（目標 80→50ms/s，用 `pet-perf-budget` 量 5 次中位數）

- 大字級、iPhone SE 照 `pet-small` 的規則驗

### R8-2 帽子與配件重畫
- **畫法統一**：每一頂都用跟角色一樣的 `P()`（描邊、亮面、錯位陰影），加材質：草帽編織紋＋帽帶、派對帽條紋＋毛球、花冠加葉子、頭巾打結＋布紋、芒草穗改成真的芒花（毛茸茸的穗）、鳳梨帽鱗片、浪花頭巾波浪

- **跟著動**：帽子掛在頭上，低頭、轉頭、跳的時候有一點點延遲擺動（不另外跑 JS：用頭的 transform 加 CSS 的 transition 延遲）
- **配件擴到 5 件**：紅圍巾（改成針織紋、尾巴會飄）、小鈴鐺（跳的時候輕輕晃；音效開時叮一聲）、登山小背包（背在背上）、領結、樹葉披風；每隻的掛點用截圖逐一確認
- **驗收**：
  - 截圖總表：13 頂 × 6 隻＋5 件配件 × 6 隻，人眼逐格看（不能蓋眼睛、不能浮在半空、不能被耳朵切掉）
  - 原有的「帽子不蓋眼睛超過 15%」檢查擴到配件
  - WebKit（`pet-webkit`）：戴帽子＋配件做完整餵食，不超出畫布
  - 逐格：戴帽子跳、低頭吃的時候帽子跟頭的距離變化 ≤ 2px（不會飛走）

## 6-2. R7 做了什麼（SW v680→v682）
- **R7-1 動作計時**：`flash()` 等「這個 class 觸發的 CSS 動畫」真的結束（`getAnimations` 前後比對），找不到動畫才用毫秒數；慢動作時保險上限跟著放大。新偵測器 `pet-anim-cut.test.js`：七隻 × 16 個動作結束那一格外框不跳（舊程式：虎的跳 19px、神龍的跳 17px、伸懶腰 7.3px、搔癢 4.8px——全部抓得到）
