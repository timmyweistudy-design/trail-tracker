# 步道詳情頁重新設計（分頁化＋美化）

日期：2026-07-21　狀態：已核准，實作中

## 背景
加入「生態」與「沿線地標」後，詳情頁變成 20+ 區塊的單一長捲軸，資訊節奏被打斷、顯得雜亂。公測期間收到「有點雜亂」的回饋。

## 目標（使用者確認三者都要）
1. 分層/收納：縮短頁面長度。
2. 重排優先順序：登山者最在意的先看到。
3. 適度視覺提升：不改色系/品牌，統一卡片與間距。

## 決策
- 詳情頁改成**真正的分頁**（一次只顯示一頁內容），取代舊的「捲動到區塊」scroll-spy。
- **固定在分頁之外**（切頁不消失）：Hero（名稱/難度/收藏）、地圖、底部「在此步道開始記錄」sticky 主按鈕。
- **4 個分頁**：概覽 · 路線 · 生態 · 周邊。

## 分頁內容對應（由上到下）
| 分頁 | 內容 |
|---|---|
| **概覽 ov** | 路況公告 → **重點數據卡（新）** → 標籤 → 分級說明(可收合) → 路面/季節/交通 → 介紹文+翻譯 → 動作列(導航/查資訊/分享/揪團/比較/原始頁) → 步道動態(trailFeed) → 活動(activity) |
| **路線 rt** | 天氣 → 海拔剖面 → 沿線地標 → 離線地圖預載 |
| **生態 ec** | 生態資訊（小黑蚊/常見動植物/iNaturalist 目擊） |
| **周邊 nb** | 設施 → 人文景點 → 周邊美食 → 附近步道 |

- 版權標示縮成一行小字，放分頁區塊最底（持久頁尾）。
- 「我的紀錄」`myLogHtml()` 已回傳空字串（早移除），不列入。

## 視覺重點：重點數據卡（概覽頁開頭）
把散落的 kv 數據收成一張四格卡：難度 / 長度 / 累積爬升 / 預估時間，各格 icon＋數值＋標籤。
- 沿用現有 token：`--r-lg` 圓角、`--sh-md` 陰影、難度色（`.badge.diff.d{n}` 同色系）當難度格強調。
- 其餘卡片（天氣/海拔/生態/周邊）統一同一種卡片外框與 `.section-title` 標題樣式，讓整頁像一套系統。
- 只有部分欄位有值時（OSM 步道欄位少）自動少格、不留空白「—」。

## 技術要點與風險
- **懶載入框**（weatherBox/profileBox/amenBox/poiBox/foodBox/trailFeedBox）在隱藏分頁仍能被填入 innerHTML → 分頁化不影響現有 loader。
- `whenVisible`（IntersectionObserver）在 `hidden` 分頁不觸發，切到該分頁才載入 → 對省 Google Places 每日配額**反而更好**；需確保切分頁時 IO 會重新觸發（display 由 none→block 進入視窗即觸發），必要時切頁時主動呼叫該頁 lazy hook。
- 移除舊 scroll-spy（`secIds` / `_detailScroll`）與浮動「跳到底部」鈕（`#detailJump`＋其 IIFE handler＋index.html 元素）——分頁後頁面短、不需要；底部改放 sticky 記錄按鈕。
- **i18n**：分頁字「概覽」「生態」各語言字典已有；新增「路線」「周邊」兩詞到 `web/js/i18n.js`(en) 與 23 個 `web/js/i18n/<code>.js`。分頁按鈕文字需經 tx() 翻譯。
- 區塊 section-title 保留可收合（分級說明等），但不再與 scroll-spy 綁定。
- 地圖點沿線地標跳位（`.wp-row` handler）維持；因地標移到「路線」分頁，點列後地圖（固定在外）仍在 → 行為正常。
