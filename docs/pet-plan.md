## 2. 共用原則（R2 起每個新功能都要照做）

**動作銜接六條**
1. 使用者操作優先於隨機待機。正在咬、正在叼、正在落地時，其他動作只能排隊。
2. 新動作從當下的姿勢接著做，不先重設成站姿。
3. 切頁、進背景、進化換角色時，舊動作立刻停；**晚到的回呼不准改到新舞台**（用世代編號擋）。
4. 果實和玩具落下前先確認角色搆得到；搆不到就換位置，不准把角色拉長去補。
5. 重要事件排隊並去重（禮物、進化、節日、紀念日）；一般台詞可以丟掉。
6. 開「減少動態效果」時，操作結果和數值回饋照樣要有；不准因為動畫關掉就變成按了沒反應（目前 `play()` 一開減少動態就直接 `return false`）。

**驗收三條**
- 「測試全綠」不算過。每項都要有**機器檢查**（逐格測試、偵測器）加上**人眼看過的截圖或錄影**。
- 每個 bug 先寫出會紅的測試再修（F1 就照這個順序）。
- 數值要附條件才能比較：哪個版本、哪一隻、哪個動作、CPU 降速幾倍、跑了幾次。

## 3. 新增的基礎項（A1～A9）

### A1 版本辨識（小）
- **怎麼做**：`debug.js` 面板標題、`ttDebug.feedPerf()` 的輸出、`scripts/pet-video.js` 的報告都加上 `SW 版本＋原生 build（App.getInfo().build，網頁版顯示 web）`。「我的 → 關於」補原生 build。
- **怎麼算好**：拿手機任意一段錄影，從畫面上就看得出是哪一版。
- **驗收**：`me.test.js` 檢查版本字串存在；手動在 iOS 確認 build 號跟 Codemagic 的 build 一樣。

### A2 統一動作仲裁（中，**本輪最重要**）
- **怎麼做**（`pet-stage.js`）：
  1. 把 `busy`／`feeding`／`playing`／`asleep`＋訪客這五個布林，收成一個 `cur = { kind, prio, phase, token }`。
  2. 新增 `claim(kind, prio)` 回傳 token、`release(token)`；**只有拿著目前 token 的人才能釋放**。這一步就修掉 F1。
  3. 優先級：使用者操作（餵食 3、玩 3、抱／摸 2）＞ 叫醒 2 ＞ 訪客 1 ＞ 待機 0。高優先遇到低優先時，低的若在「可中止」階段就中止，否則等它到下一個可中止點。
  4. 每個動作標出階段：`interruptible`（待機、走路）／`waitable`（落地中、轉身中）／`atomic`（咬住到吞下、尾巴送果實）。
  5. 世代編號 `gen`：`bind`／`unbind`／換階段時 +1，所有 `await` 之後都要檢查 `g === gen`，不一樣就收拾離開。
  6. `pet.js` 的 `feedPet()`、`poke()`、玩松果按鈕都改問 `PetStage.canStart(kind)`，被擋時用 `petSwapText` 說一句（「在吃東西，等我一下～」已經有了，補上「朋友來玩了，等等喔」「牠在睡覺」）。
- **怎麼算好**：連按、在動作中途切頁、進背景再回來、餵到一半進化，都不會疊動作、不會留下道具、不會突然回到初始姿勢。
- **驗收**：`pet-stage.test.js` 新增一組「交接矩陣」：{待機 act 進行中, 叫醒中, 訪客中, 玩中, 吃中} × {餵、玩、抱、訪客、切頁、hidden}，共 30 格；每格檢查：舞台上殘留的 `.ps-berry`／玩具數量、`cur` 最後回到 idle、單一擁有者偵測器 0 違規、沒有 pageerror。

### A3 統一物件接觸（中）
- **怎麼做**：果實和松果共用一個狀態機 `falling → rest(ground|cloud) → held(mouth|tail|paw) → consumed|returned`。交接那一格先算出物件的世界座標，再換掛點，**同一格寫入**，不留一格空檔（之前「閃兩下」就是因為有一格空檔）。
- **怎麼算好**：咬住後果實跟著嘴、尾巴捲起後跟著尾尖、交接那一格看不出跳。
- **驗收**：`pet-motion.test.js` 在每次換掛點的前後 3 格，檢查位移 ≤ 1.5px／格；七隻都要跑。

### A4 獎勵結算稽核（小）
- **怎麼做**：列出所有會改數值的入口（餵食、好友送果實 `petGiftBerries`、禮物、進化、每日任務、季節配件、買帽子），每個入口確認是「先結算、後動畫」，而且有冷卻或當天鍵可以擋重複。
- **驗收**：新增測試，每個入口在動畫中途 reload，數值只變一次。

### A5 存檔合併規則＋格式版本（中，修 F3／F4）
- **怎麼做**（`storage.js`）：
  1. `exportAll()` 多一個 `petV: 1`。
  2. 每個夥伴鍵定一條合併規則，寫成表：
     - 只會變大的計數（`berry_spent`、`berry_bonus`、`berry_picked`、`feedkm`、`stage`、`base`、`aff`）→ 取較大值
     - 清單（`diary`、`gifts`、`props`、`hats_owned`、`badges_got`）→ 依 id／時間聯集
     - 偏好（`name`、`hat`、主題）→ 本機有值就留本機
     - 時間戳（`fed_t`、`gift_t`、`aff_t`）→ 取較新的值
  3. 規則分兩種模式：`replace`（換機還原，本機是空的才允許整包覆蓋）、`merge`（照上面的表）。
  4. `importAll()` 回傳 `{ applied, skipped, errors }`，`me.js` 顯示「已還原 N 項，略過 M 項」。
  5. 讀到舊格式（沒有 `petV`）時，先轉成新格式再合併。
- **怎麼算好**：同一個檔案還原兩次，結果一樣；用舊備份合併，不會讓果實變多、進度倒退或日記消失。
- **驗收**：`storage.test.js` 新增：舊格式、重複還原、本機比較新、備份比較新、檔案壞掉一半、還原後重開 App 不會重領禮物。

### A6 功能能力檢查（小）
- **怎麼做**：音效（AudioContext）、震動（iOS 網頁沒有 `navigator.vibrate`，原生走 Capacitor Haptics）、搖手機（iOS 要先 `DeviceMotionEvent.requestPermission()`）、存照片（分享面板）、小工具（App Group 有沒有開）。不支援的就**不顯示開關**，或改成替代操作。
- **驗收**：測試裡把各 API 拿掉，畫面上不能出現按了沒反應的按鈕。

### A7 七隻視覺驗收表（中）
- **怎麼做**：新增 `scripts/pet-acceptance.js`，固定種子、`__psNoIdle`、`__psSpots`，每隻跑一樣的序列（待機 → 3 顆果實 → 玩 → 抱 → 睡／醒 → 戴帽子），輸出**一頁 HTML 的接觸表**（每隻每個階段抓 6 格，加上逐格測試的數字）。結果寫在本文件第 4 節的表格，每隻標「通過／未通過＋原因」。
- **怎麼算好**：每隻都有明確的結論，而且每個結論都看得到證據截圖。

### A8 夥伴不拖慢健行（小）
- **怎麼做**：記錄頁、地圖頁開著的時候，夥伴舞台的 rAF 和計時器要是 0（「看不到就停」已經做了，這裡是加檢查）；在 CPU 降速 4 倍下記錄 10 分鐘，量長任務。
- **驗收**：新增測試，切到記錄頁 5 秒內，`PetWalk` 沒有任何一格在跑。

### A9 測試時鐘（小，合併原 36、38）
- **怎麼做**：把 `window.__ps.tod`、`Date.now()`、`new Date()` 收成一個 `ttClock`（只有測試面板和測試可以設），作息、冷卻、禮物、節日、紀念日、提醒全部讀它。測試面板加「時間快轉」：清晨、黃昏、深夜、節日、紀念日、+8 小時。關掉之後完全還原，而且**不寫進正式存檔**（沿用 dbg 標記）。
- **驗收**：測試在午夜前後 1 分鐘、節日前後 1.5 天的邊界都要跑，而且要固定 `timezoneId: "Asia/Taipei"`。
